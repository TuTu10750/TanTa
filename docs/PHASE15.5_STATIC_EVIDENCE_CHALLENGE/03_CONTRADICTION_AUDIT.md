BATCH 05 · 最强反对者审计（对每条现有结论提出最强反例）

## 反例 1
- 原结论：APK 静态扫描没有业务域名，因此业务域名不在 APK 中
- 最强反例：字符串扫描只覆盖可打印 ASCII；域名可能以加密/编码/分片形式存在而未被识别。且静态分析只覆盖当前下载的包（三份哈希不同），不代表爸爸那份包也没有。
- 反例有证据支持：是（本轮前 so 扫描发现 XOR 混淆结构；APK 动态换包已确认）
- 是否修正：是
- 修正表述：在已检查的反编译源码、so 字符串和当前包中未发现明文业务域名；不排除其他包版本或非明文形式
- 仍未知：是

## 反例 2
- 原结论：Netshield 负责远端转发，因此业务域名一定由远程配置提供
- 最强反例：so 内 getCheckServersFromOSS 等符号只证明存在配置拉取代码结构，不证明它一定下发业务域名；也可能只下发 IP 路由、证书、黑名单，或仅用于反检测；业务域名可能由 Java 层某处构造后被代理读取。
- 反例有证据支持：是（Java 层全是无域名 URL，未见任何域名字符串；native 符号语义不足以确定内容）
- 是否修正：是
- 修正表述：Netshield 具备远端配置拉取结构；配置内容（是否含业务域名）为 INFERRED
- 仍未知：是

## 反例 3
- 原结论：HTTP 与 WS 使用不同端口，因此两者属于不同远端系统
- 最强反例：不同 ruleName 可以映射到同一台服务器的同一进程，只是不同本地监听端口/不同协议入口；端口分离是客户端路由策略，不等于后端系统分离。
- 反例有证据支持：是（无任何证据显示 G/H/I/J 指向不同远端主机）
- 是否修正：是
- 修正表述：G/H/I/J 是不同本地端口规则；远端拓扑未知
- 仍未知：是

## 反例 4
- 原结论：data.facegl.com 是空壳，因此整个域名没有业务用途
- 最强反例：appapi 只有 Auth/Gift 两个控制器，只说明 appapi 模块被裁剪；该域名可能承载 portal/page、H5、静态资源、支付回调或其他模块；美狐 SDK 域名本身有其合法用途。
- 反例有证据支持：是（前轮只测了 /appapi/ 路径，未穷举该域名其他路径）
- 是否修正：是
- 修正表述：data.facegl.com 不是探他 appapi 主目标；其他用途未确认
- 仍未知：是

## 反例 5
- 原结论：公共参数函数存在，因此所有接口都使用相同公共参数
- 最强反例：源码已有直接反例——o12.java:105 手工拼接 uid/language/token/anchor_id；a1/j0 拼接 orderid/user_type；i22/h22 把 wg1.w/x 直接传给播放器；只有 s92.java 明确调用 j30.p()。请求封装方式至少 4 种。
- 反例有证据支持：是（本轮源码直接核实）
- 是否修正：是（该结论被 CONTRADICTED）
- 修正表述：存在多种请求封装；j30.p() 仅是其中一种
- 仍未知：各封装最终是否由 netshield 统一补全 — UNVERIFIED

## 反例 6
- 原结论：客户端存在某个模型，因此服务器返回的数据一定符合该模型
- 最强反例：Bean 类是客户端期望模型（fastjson 解析目标），服务端真实返回可能缺字段、多字段或类型不同；缺字段时 fastjson 可能给 null/默认值而不报错。
- 反例有证据支持：是（通用程序事实；无运行时响应佐证）
- 是否修正：是
- 修正表述：模型为 CLIENT_EXPECTED_MODEL；SERVER_RESPONSE_UNVERIFIED
- 仍未知：是

## 反例 7
- 原结论：证书 CN 与业务域名无关，因此证书资产与业务网络无关
- 最强反例：server.cer 是 assets 内 pinned cert；即使 CN=data.facegl.com 属于美狐 SDK，native proxy 可能复用该证书链或同一 CA 体系保护业务连接；证书资产与网络路径的关系不能仅凭 CN 否定。
- 反例有证据支持：部分（证书锁定存在；但证书用途属于 SDK 的判断来自 CN 与实测，未见完整证书链分析）
- 是否修正：是（弱化）
- 修正表述：server.cer CN 非探他 appapi 域名；其与 native 代理 TLS 的关系未完全排除
- 仍未知：是

## 反例 8

- 最强反例：startService("998", "de62d3e947ab10496b1c9090915d2d04") 第二个参数可能是 app 标识、渠道码、配置版本号或签名摘要，不一定是 AES/MD5 密钥；没有 so 反编译证据证明其作为密钥参与解密。
- 反例有证据支持：是（无调用链证据）
- 是否修正：是
- 修正表述：称为"32 位启动参数"或"启动凭证字符串"，不认定具体用途
- 仍未知：是

- 反例有证据支持：是（本轮前实测：全量 XOR 只命中 1 条）
- 是否修正：是

- 仍未知：是

## BATCH 06 · 停止边界判定

- wg1.java 24 条 URL 常量
- j30 的 G/H/I/J 四个 ruleName 字符串及用途（Fuel/WS/心跳/LinkForty）

### 是否有理由继续非运行时研究
